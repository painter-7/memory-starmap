# 数据接入清单（Ingest）

按顺序过一遍，能省掉 80% 的「星图长得不对」问题。

## 1. 先确认三件事

| 问题 | 不满足会怎样 |
| --- | --- |
| 每条记忆有**可解析的日期**吗 | 日期认不出 → 整条丢弃 → 天数变少、日期星错位 |
| 文本里有没有包裹层（任务壳、系统提示、引用块） | 壳没剔干净 → 壳里的高频词占满 `df` 榜 → 连边全是废话 |
| 记忆条目的粒度是否一致 | 有的 20 字有的 3000 字 → 长条目吃掉所有连边 |

## 2. 清洗

`src/build.py` 里的 `NOISE` 是正则列表，**只在这里加规则**：

```python
NOISE = [
    re.compile(r"\[CronJob\][^:：]*[:：]?"),
    re.compile(r"<system_reminder>.*?</system_reminder>", re.S),
    # 加你自己的：
    re.compile(r"^\[自动\]\s*"),         # 自动任务前缀
    re.compile(r"\(from [^)]*\)"),       # 来源脚注
]
```

清洗后再判长度门槛 `min_len`（默认 20）：短于此的条目通常是寒暄、状态字、单字回复，对拓扑没有贡献，留着只会让孤点变多。

## 3. 连边质量调参

先跑一次，看 `links/nodes` 比值，正常落在 **1.2 ~ 2.0**：

| 现象 | 原因 | 改哪个 |
| --- | --- | --- |
| 比值 < 0.8，孤点一大片 | `df_max` 太小，词全被过滤 | 调大 `df_max`（25 → 40） |
| 比值 > 4，成一团毛线 | `df_min` 太小或短条目太多 | 调大 `df_min`（2 → 3），或提 `edge_min_score` |
| 每条边都很像 | `edge_per_node` 太高 | 降到 2，宁可稀疏 |
| 跨天完全不通 | 日期分层太散，同日才有共现 | 这是设计使然；要跨天连通靠证据链，先补 `evidence` 字段 |

## 4. 证据链

只有 `evidence` 长度 ≥ 20 且能在**同日**目标源里原文命中时才连强边。想提高命中率：

- `evidence` 用原话片段，别用概括（概括是模型改写过的，原文里不存在）；
- `evidence_target_sources` 指向那个存原话的源（本项目里是 `cold`）；
- 命中率低就先去数据侧补证据，别在算法上找补。

## 5. 常见源映射

| 你的数据 | type | 关键字段 |
| --- | --- | --- |
| SQLite 记忆库 | `sqlite` | `day`, `text`, `kind`, `importance→weight`, `evidence` |
| 导出的 JSONL | `jsonl` | 同上，一行一条 |
| 按日 Markdown 笔记 | `markdown` | 文件名须以 `YYYY-MM-DD` 开头 |
| CSV | 先转 JSONL | — |

> SQLite 一律 `mode=ro` 只读打开。别为了省事连主库写连接，构建脚本不该有写权限。
