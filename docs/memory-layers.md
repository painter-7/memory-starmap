# 分层数据到星图的映射

本文是 [`architecture.md`](architecture.md) 第 3 节与第 6.2 节的展开，说明各记忆层在星图构建中的角色、配置方式与取舍依据。

## 1. 映射总表

| 层 | 数据类型 | 是否作为节点 | 是否参与连边 | 星图中的角色 | 建议 loader |
| --- | --- | --- | --- | --- | --- |
| L1 常驻层 | 长期偏好、进行中事项 | 否 | 否 | 不接入 | — |
| L2 日目录层 | 按日事件段 | 是（全量） | 词面共现 | 时间骨架，保证日期星连续 | `markdown` |
| L3 叙事层 | 第一人称长文 | 可选（采样） | 词面共现 | 少量高信息密度节点 | `markdown` |
| L4 原文层 | 原始消息 | 否（仅采样展示） | 仅作为证据链目标 | 证据来源 | `sqlite`（只读） |
| L5 结论层 | `fact / lesson / preference` | 是（全量） | 词面共现 + 证据链 | 节点主体、跨天连边主力 | `sqlite`（只读） |

`examples/sources.example.json` 按上表配置：L5 与 L2 提供节点，L4 仅列入 `evidence_target_sources`。

## 2. 三类数据的职责划分

实现星图前需明确三个输入：

1. **节点源**：承载结论与事件的层，要求单条可独立成立。
2. **日期源**：按日组织的层，决定日期星的位置与时间轴密度。
3. **证据源**：保存原文的层，决定跨天边能否建立。

三者可由不同表提供，也可由同一表的不同字段提供，但语义必须区分。混用会导致节点文本与证据文本同源，证据链退化为共现边。

## 3. 取舍依据

### 3.1 L1 不接入

常驻层保存的是全局性的现状描述，条目之间天然全相关。接入后将与多数节点建立边，压缩权重分布，使稀有词边失去区分度；且内容每日变动，坐标不稳定。这类内容应通过检索访问，不通过拓扑访问。

### 3.2 L4 不作为节点，但决定跨天连通性

L4 是唯一保存原文的层。`evidence` 字段的语义是：结论对应的原始表述在同一日期范围内是否出现于其他语境。该判断基于原文字符串命中，而非改写后的摘要。

若将 L4 全量铺为节点，数万条消息将使结论节点在视觉与权重上被淹没。仅作为证据源时，跨天关系才具备可解释性。

需要在星图中展示原文时，采用按日采样或仅展示被引用条目，不改变全量铺点的边界。

### 3.3 节点与边的准入

- **节点**：单独阅读该条文本，能否还原当时的判断或事件。不能则属碎片，保留在 L4 供检索。
- **边**：能否用一句话说明两个节点的关联。不能则属共现噪声，应调整 `df_max` 与 `edge_min_score`，不以增加边数方式补偿。

## 4. 规模参考

以节点数 5k 量级的部署为例：

- 节点构成：结论层约 27%，日目录层约 8%，其余来自叙事层与采样；
- 边构成：多数为稀有权重词的同日共现；跨天边占比通常低于 10%，但决定主题脊线；
- 日期星仅覆盖有写入的日期，不补空日。

上述比例为量级参考，随语料与阈值变化，不作为验收标准。可观测指标见 `architecture.md` 第 7 节。

## 5. 接入其他系统的检查项

不要求目标系统同为五层。接入前确认以下三项：

1. 承载结论的表：作为节点源，全量接入；
2. 按日组织的目录或表：作为日期源，`markdown` loader 可直接读取目录；
3. 保存原文的表：列入 `evidence_target_sources`，并确认 `evidence` 字段可在该表中按原文字符串命中。

三项均可定位时，`sources.json` 可在十分钟内完成配置。无法定位时，问题位于记忆系统结构本身，星图会将其放大而非掩盖。

## 6. 两项约束

- **不使用上下文摘要作为节点文本。** 摘要中「用户询问了 X」类句式词面重合度高，会导致全图连成单一连通分量。节点文本需保留主语与结论，对话壳由 `build.py` 的 `NOISE` 规则或自定义正则剔除。
- **不以全量原文补充节点密度。** 节点数量不足时应调整 `min_len` 与 `df_max`，不扩大数据接入边界；后者会使星图从导航工具退化为点云。
