# 技术方案：长期记忆分层与星图可视化

本文描述一套可迁移、可维护的 AI 长期记忆系统，以及构建在其上的三维星图视图。方案分为两部分：**记忆如何分层、写入与检索**，以及**如何将档案渲染为可导航的星图**。

文中不含具体部署环境、账号与私有语料；路径与容量均为参考值，实施时按实际规模调整。

参考实现：`src/`（构建器与布局服务）、`web/`（前端）、`examples/`（数据源配置）。分层映射细节见 [`memory-layers.md`](memory-layers.md)，产物字段见 [`schema.md`](schema.md)。

---

## 1. 问题定义

长期记忆系统的失效通常不源于存储容量，而集中在以下四类：

| 症状 | 成因 | 本文对应机制 |
| --- | --- | --- |
| 长会话中出现重复提问、循环推理 | 上下文叠加多层摘要，信息在压缩链上失真 | 分层存储 + 闲置边界压缩 |
| 能确认事件存在，但无法还原当时的判断依据 | 仅保存结论，未保留原始表述 | 原文层 + 证据字段 |
| 检索可用，但缺乏时间与主题的整体感知 | 仅提供结构化查询，缺少拓扑视图 | 星图 |
| 更换设备或模型后状态丢失 | 记忆依附于产品会话，而非可迁移载体 | 文件与 SQLite 为唯一真源 |

**非目标**：不涉及嵌入模型训练、多模态记忆，也不承诺全量召回。分层可解决容量、成本与结构腐化；无法解决「换一种表述即检索不到」（属检索层）与「结论是否正确」（属模型能力）。

**范围边界**：本文只覆盖记忆分层与星图渲染，不含配置层与行为策略。

## 2. 总体架构

```
        ┌──────────── 写入链路 ────────────┐
对话 ──►│ 原始落库 ──► 按日成段 ──► 夜间提炼结论 │
        └───────┬────────────┬────────────┬────────┘
                ▼            ▼            ▼
             L4 原文层     L2 日目录层   L5 结论层
                │            │            │
        ┌───────┴────────────┴────────────┴────────┐
        │ L1 常驻层：长期偏好、稳定结论、进行中事项（≤3800 字）│
        │ L3 叙事层：第一人称长文，低频写入             │
        └───────┬──────────────────────┬───────────┘
                ▼                      ▼
        检索（关键词 + 向量 + 证据校验）   星图构建（点/边/布局/前端）
```

三条约束：

1. **单层单一职责**，且可回答「缺该层时，哪一类查询会失败」。
2. **原始层只追加，结论层可覆盖但不删除**；覆盖通过 `superseded_by` 表达。
3. **所有层均落为文件或 SQLite**，不依赖特定模型服务，路径可迁移。

---

## 3. 分层规格

### L1 常驻层

| 项 | 规格 |
| --- | --- |
| 内容 | 长期偏好、稳定结论、进行中事项、关键路径 |
| 容量 | 目标 ≤3800 字，硬上限 5000；超限时尾部内容被静默截断 |
| 写入 | 不直接修改；日常写入 `hot_pending.md` 的 `## ` 段，每日定时合批应用 |
| 准入判据 | 缺少该条会导致下一轮执行错误；仅为「避免遗忘」的内容写入 L2/L5 |
| 失败模式 | 混入流水账，占用预算并挤出关键约束 |

### L2 日目录层

| 项 | 规格 |
| --- | --- |
| 存储 | `daybook/YYYY-MM-DD.md`，按 `##` 分段，一段一事件 |
| 必填 | 时间、说话方、事件结论；说话方分列（`user:` / `assistant:`） |
| 写入时机 | 每日会话结束后统一生成，非实时 |
| 准入判据 | 作为当日事件的主要检索入口；缺失将导致时间轴空档 |
| 失败模式 | 单段承载多事件，导致检索召回噪音 |

### L3 叙事层

| 项 | 规格 |
| --- | --- |
| 内容 | 第一人称复盘，包含判断、情绪与未结论事项 |
| 频率 | 低频，按事件或按周写入 |
| 作用 | 保留语气与推理过程；摘要层无法承载该信息 |
| 判据 | 需要还原「当时为何如此判断」时写入本层，不进入 L5 |

### L4 原文层

| 项 | 规格 |
| --- | --- |
| 存储 | SQLite，`(id, day, role, text, conversation_id)`，时间索引 + 向量索引 |
| 写入时机 | 每轮会话结束即写入，不做加工 |
| 用途 | 关键词召回、原文核对、星图证据源 |
| 约束 | 只读为主，不参与上下文注入；单条粒度为一句或一段 |
| 失败模式 | 被直接注入上下文，挤占有效预算 |

### L5 结论层

| 项 | 规格 |
| --- | --- |
| 存储 | SQLite，`(id, day, kind, text, evidence, weight, superseded_by)` |
| `kind` | `fact` / `lesson` / `preference` |
| 写入时机 | 每日凌晨对 L2 做一次提炼 |
| 强制字段 | `evidence`：从 L4 原样摘录的一句原文，不得改写 |
| 覆盖语义 | 新结论写入时，旧行标记 `superseded_by`，保留原记录；检索默认过滤 |
| 准入判据 | 单条可独立成立，脱离上下文仍可还原当时的判断 |
| 失败模式 | 仅存结论、缺失证据，导致跨天关联与出处校验失效 |

## 4. 写入链路

### 4.1 单轮会话

1. 原始消息写入 L4，附带 `role`、时间戳、`conversation_id`。
2. 不进行即时摘要。实时摘要会截断进行中的推理链。
3. 当日结束后，将全天内容压缩为 L2 的 5~15 个事件段，按说话方分列。
4. 凌晨从 L2 提炼 L5，逐条回 L4 摘取原文作为 `evidence`。

### 4.2 压缩策略

仅在**闲置边界**执行压缩：

- 会话进行中，压缩阈值设为 0.95，基本不触发；
- 空闲 ≥30 分钟、无后台任务、上下文超过阈值，三者同时满足时，先完成 L2/L5 写入，再执行压缩；
- 以下情况放弃压缩：要点未写完、记忆未落盘、压缩器未识别出可压缩区间。

依据：会话中途压缩成本最高且不可逆，压缩后仍需重新建立上下文。

### 4.3 结论记录示例

```jsonc
{
  "id": 412,
  "day": "2026-11-06",
  "kind": "lesson",
  "text": "任务切换前需等待在途作业排空，否则恢复后按过期状态执行",
  "evidence": "当前作业尚未结束，切换会导致状态回退",
  "weight": 0.85,
  "superseded_by": null
}
```

`evidence` 必须能在 L4 中按原文字符串命中；该约束是星图跨天连边与检索出处校验的前提。

---

## 5. 检索链路

1. **L5 优先**：关键词与向量双路召回，按 `weight` 与时间衰减排序，过滤已覆盖记录。
2. **L2 补充**：按日期或主题召回事件段。
3. **L4 校验**：以 L5 的 `evidence` 反查原文，确认结论未被改写。
4. **未命中处理**：返回空结果并记录查询词，进入补写队列，不生成猜测性回答。

出处校验为强制步骤：输出结论时同步给出日期与原文片段。结论与出处不一致的代价高于拒答。

## 6. 星图管线

### 6.1 处理流程

```
sources.json ─► 数据读取（sqlite 只读 / jsonl / 按日 markdown）
             ─► 清洗（任务壳、引用块、URL、图片占位、压缩标记）
             ─► 建点（L5 与 L2 全量，L3 可选，L4 仅作证据源）
             ─► 连边（稀有权重词共现 / 证据链同日命中）
             ─► 布局（布局服务 → 本地 numpy → 纯 Python，三级降级）
             ─► starmap.json（fingerprint 缓存）
             ─► 前端（Canvas 2D 手工三维投影；逐日回放、聚焦、筛选、详情）
```

### 6.2 点与边

**点**：来源于 L5 与 L2；L3 按需采样；L4 不作为点，只作为证据源。全量铺入 L4 将使星图退化为点云，失去导航价值。

**边 A（共现）**：同一文本内出现稀有词（`df ≤ df_max`）即连边，权重按 `log(N/df)` 累积并归一化。适用于同日稠密关联。

**边 B（证据链）**：若 A 点的 `evidence` 原文在 B 点所属源中命中，则连跨天边，权重固定 1.0。跨天主题脊线主要依赖该机制。

**生成约束**：每点保留最强 `edge_per_node` 条边；去重、无自环；边以 `a < b` 存储。

### 6.3 布局

- 优先调用 `layout_server.py`，支持远端或本机；
- 服务不可达时读取缓存坐标；
- 缓存缺失时使用本机 numpy 力导向；
- 最终降级为纯 Python 实现。
- 任一步失败仅影响坐标，不影响产物完整性。产物携带 `fingerprint`（节点 key 集合的 SHA-1 前 16 位），指纹未变则跳过重算。

### 6.4 前端

- 零依赖、零构建，仅 `index.html` + `app.js`；
- Canvas 2D 手工实现三维投影，不引入 WebGL 框架，降低部署体积与白屏风险；
- 功能：逐日回放、点选聚焦、类型筛选、详情卡（摘要 / 全文 / 证据）；
- 验收：静态服务器启动后以真实浏览器加载，控制台无报错，首屏可交互。

## 7. 验收指标

| 对象 | 指标 | 参考阈值 |
| --- | --- | --- |
| L2 写入 | 前一日页面中，助手侧原话条数 | 0 条视为写入失败 |
| L5 证据 | 随机抽取 20 条，`evidence` 在 L4 原样命中率 | <90% 需回炉重提 |
| 检索 | 固定问题集 Top-5 命中率，关键词与自然语言分组统计 | 分组记录，不合并为单一指标 |
| 星图 | 孤点比例（无任何边的节点占比） | >25% 需调整分词或阈值 |
| 星图 | 跨天边占比、日期星连续天数 | 断档 >3 天需检查日收尾任务 |
| 构建 | 全量构建耗时、fingerprint 缓存命中率 | 记录基线，耗时翻倍触发排查 |
| 前端 | 浏览器控制台错误数、首屏可交互、竖屏布局 | 每次修改渲染层均需回归 |

## 8. 运维与成本

- **时间表一致性**：常驻层合批、日收尾、夜间提炼各有固定时点；任一环缺失，次日输入为空。需定期核对调度表与实际执行记录。
- **重任务异步化**：提炼、向量索引、星图构建均转入后台任务，前台仅返回状态；否则一次构建会阻塞会话数十秒。
- **SQLite 备份**：WAL 模式下直接复制 `.db` 可能得到不完整快照，应使用 `sqlite3 .backup` 或先执行 checkpoint。
- **成本结构**：分层本身不降低 token 消耗；节省来自「仅常驻层进入上下文，其余按需检索」。将 L4 注入上下文是成本最高的用法。

## 9. 已知问题

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 单段多事件 | 检索召回噪音 | 一段一事件，段首标注日期与说话方 |
| 摘要仅记录单侧 | 次日仅能还原对方行为 | 按说话方分列，助手侧保留原话 |
| 实时摘要 | 推理链被截断，出现循环 | 仅在闲置边界压缩 |
| 以全量原文补密度 | 星图退化为点云 | 调整 `min_len` / `df_max`，不改变数据边界 |
| 常驻层进入星图 | 节点全连接，权重结构被压平 | L1 不参与星图 |
| 摘要直接作为点 | 句式高度相似，边权重失真 | 点文本保留主语与结论，清洗对话壳 |
| 随机连边 | 视觉可看但不可解释 | 仅连真实关系 |

---

## 10. 最小实现路径

1. 建立 `cold.db`（原文）与 `dream.db`（结论 + evidence）。
2. 实现日收尾任务，生成 `daybook/YYYY-MM-DD.md`，按说话方分段。
3. 实现夜间提炼任务，输出 `fact / lesson / preference` 并回填原文证据。
4. 常驻层以单个 Markdown 文件维护，控制字数并定期合批。
5. 部署星图：`pip install numpy`，复制 `examples/sources.example.json` 并修改路径，执行 `python3 src/build.py --sources sources.json`。
6. 以 `python3 -m http.server` 加载 `web/`，按第 7 节完成验收。

基础链路可在一天内跑通；长期可用性取决于第 4 节的写入纪律与第 7 节的验收是否持续执行。
